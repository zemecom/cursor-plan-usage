# Cursor Plan Usage

Неофициальное расширение для Cursor. Показывает расход включённого тарифа того аккаунта, под которым открыт редактор. Ключ Admin API и переменная `CURSOR_API_KEY` не используются.

В статусбаре строка выглядит так: `Team | Grok 30.6% | Other 0.0%`.

- **Grok** — доля Cursor Models (`autoPercentUsed`).
- **Other** — доля Other Models (`apiPercentUsed`).
- Общий смешанный процент в интерфейс не выводится.

Клик по строке открывает дашборд: карточки тарифа, столбцы по дням, таблица моделей и список событий. Пока панель открыта, она обновляется с тем же интервалом, что и статусбар. Предупреждающий фон появляется, когда больший из двух процентов достигает 80%, красный — при 100%.

## Установка

Нужен вошедший в Cursor аккаунт и `sqlite3` в `/usr/bin/sqlite3`. Расширение читает сессию только на чтение из локальной базы редактора и никуда её не записывает.

```bash
git clone https://github.com/zemecom/cursor-plan-usage.git
ln -sfn "$(pwd)/cursor-plan-usage" "$HOME/.cursor/extensions/local.cursor-plan-usage"
```

Имя каталога в `~/.cursor/extensions` без суффикса версии. После создания ссылки выполни **Developer: Restart Extension Host**. Кнопка **Restart Extensions** в списке расширений появляется, когда версия в `package.json` отличается от версии, которую хост уже загрузил.

## Настройки

Команда **Cursor Plan Usage: открыть настройки** или кнопка «Настройки» в дашборде открывает раздел `cursorPlanUsage`.

| Настройка | По умолчанию | Смысл |
| --- | --- | --- |
| `cursorPlanUsage.pollIntervalMinutes` | 1 | Как часто обновлять статусбар, от 1 до 60 минут |
| `cursorPlanUsage.dashboardDefaultRange` | `billingCycle` | Период графиков при открытии: `billingCycle`, `30d`, `7d`, `1d` |

Проценты в карточках всегда за текущий биллинг-цикл. Переключатель периода меняет только графики и список событий.

## Откуда цифры

Тариф и проценты запрашиваются у `api2.cursor.sh` от имени текущей сессии Cursor: план, расход цикла и разбивка по моделям. Список событий запрашивается у `cursor.com`. Если события помечены почтой, в таблице остаётся только почта текущего аккаунта. Сама почта в интерфейс не выводится.

Запрос списка событий ограничен по времени. Если он не успевает, дашборд всё равно показывает модели текущего цикла и пишет, что события не загрузились.

## Разработка

Зависимостей нет, сборки нет. Логика в трёх файлах: `extension.js` (статусбар и панель), `usage.js` (сессия и запросы), `dashboard.js` (разметка панели).

Проверка синтаксиса:

```bash
node --check extension.js && node --check usage.js && node --check dashboard.js
```

Правка этих файлов не подхватывается уже запущенным хостом. Подними версию в `package.json` и перезапусти хост расширений.
