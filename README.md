# Cursor Plan Usage

Неофициальное расширение для Cursor. Показывает расход включённого тарифа того аккаунта, под которым открыт редактор. Ключ Admin API и переменная `CURSOR_API_KEY` не используются.

В статусбаре строка выглядит так: `Team | $(plan-grok) 30.6 | $(symbol-misc) 0.0`. Знак `%` не пишется. Значок карты `$(credit-card)` добавляется в конец только когда по сверхтарифному расходу уже есть трата.

- **Grok** — доля Cursor Models (`autoPercentUsed`). В строке состояния это свой значок `plan-grok` из файла `media/grok.ttf` (формат TrueType: Cursor отдаёт `.ttf` даже когда папка расширения — ярлык). На карточке дашборда тот же контур как SVG.
- **Other** — доля Other Models (`apiPercentUsed`). В строке состояния это встроенный значок `symbol-misc`.
- **OD** — доля индивидуального, а если его нет, командного лимита сверх тарифа. В строке состояния это встроенный значок `credit-card`. При нулевом расходе не показывается.
- Общий смешанный процент в интерфейс не выводится.

Клик по строке открывает дашборд: карточки тарифа, столбцы по дням, таблица моделей и список событий. Карточка OD появляется вместе со строкой в статусбаре. На карточке Grok вместо слова стоит тот же логотип. Пока панель открыта, она обновляется с тем же интервалом, что и статусбар. Предупреждающий фон появляется, когда больший из показанных процентов достигает 80%, красный — при 100%.

## Установка

Нужен вошедший в Cursor аккаунт и `sqlite3` в `/usr/bin/sqlite3`. Расширение читает сессию только на чтение из локальной базы редактора и никуда её не записывает. Если значение начинается с `cursor-safe-storage:v1:`, на macOS оно расшифровывается ключом из связки `Cursor Safe Storage` и только потом уходит в запрос тарифа. Если доступ к связке запретить, следующий диалог появится после команды «Обновить», кнопки в дашборде или смены периода, а не на каждом опросе. В удалённом окне строка считается на локальной машине.

```bash
git clone https://github.com/zemecom/cursor-plan-usage.git
ln -sfn "$(pwd)/cursor-plan-usage" "$HOME/.cursor/extensions/zemecom.cursor-plan-usage"
```

Имя каталога в `~/.cursor/extensions` без суффикса версии. После создания ссылки выполни **Developer: Restart Extension Host**.

## Настройки

Команда **Cursor Plan Usage: открыть настройки** или кнопка «Настройки» в дашборде открывает список в самом расширении: интервал обновления и период дашборда. Значения пишутся в те же ключи `cursorPlanUsage.*`.

| Настройка | По умолчанию | Смысл |
| --- | --- | --- |
| `cursorPlanUsage.pollIntervalMinutes` | 1 | Как часто обновлять статусбар, от 1 до 60 минут |
| `cursorPlanUsage.dashboardDefaultRange` | `billingCycle` | Период графиков при открытии: `billingCycle`, `30d`, `7d`, `1d` |

Проценты в карточках всегда за текущий биллинг-цикл. Переключатель периода меняет только графики и список событий.

## Откуда цифры

Тариф и проценты запрашиваются у `api2.cursor.sh` от имени текущей сессии Cursor: план, расход цикла и разбивка по моделям. Список событий запрашивается у `cursor.com`. Если события помечены почтой, в таблице остаётся только почта текущего аккаунта. Сама почта в интерфейс не выводится.

Запрос списка событий ограничен по времени. Если он не успевает, дашборд показывает модели текущего цикла и пишет, что события не загрузились. Успешно загруженный пустой период оставляет таблицу моделей пустой. Дни без событий остаются на графике с нулём. Обрезанный длинный список по-прежнему показывает только дни, которые попали в ответ.

## Разработка

Зависимостей нет, сборки нет. Логика в `extension.js` (статусбар и панель), `settings.js` (интервал и период), `session.js` (чтение и расшифровка сессии), `usage.js` (запросы), `usage-model.js` (сводка) и `dashboard.js` (разметка панели).

Проверка:

```bash
node --check extension.js && node --check session.js && node --check settings.js && node --check usage.js && node --check usage-model.js && node --check dashboard.js && node --test
```
