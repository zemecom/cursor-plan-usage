# AGENTS.md — cursor-plan-usage

Локальное расширение Cursor. Источник поведения — `extension.js`, `session.js`, `usage.js`, `dashboard.js` и `package.json`. Репозиторий: `https://github.com/zemecom/cursor-plan-usage`.

## 1. Стек и запуск

- CommonJS, без `npm` и без сборки. Хост — процесс расширений Cursor (`engines.vscode` в `package.json`). `extensionKind` равен `ui`: в удалённом окне расширение остаётся на локальной машине, где лежат база и связка ключей.
- Код выполняется на хосте, не в Docker. Сессия читается через `/usr/bin/sqlite3` из `state.vscdb` в режиме `mode=ro`. Значение `cursor-safe-storage:v1:` на macOS расшифровывается ключом связки `Cursor Safe Storage` до любого запроса. После отказа в доступе к связке повторный диалог появляется только по явному обновлению: команда, кнопка дашборда, клик по периоду или повторное открытие панели.
- Установка: симлинк `~/.cursor/extensions/zemecom.cursor-plan-usage` на корень этого репозитория. Имя каталога без суффикса версии. `publisher` в `package.json` — `zemecom` (полный id расширения `zemecom.cursor-plan-usage`).
- После правки кода подними `version` в `package.json` и то же значение у `zemecom.cursor-plan-usage` в `~/.cursor/extensions/extensions.json`. Cursor следит за `extensions.json`: запись ключуется идентификатором и версией. Смена версии в профиле заставляет заново прочитать расширение с диска. Если версия в `package.json` отличается от уже загруженной хостом, в карточке появляется Restart Extensions. Хост сам не перезапускай.

## 2. Инварианты

- В статусбаре только метры значками `$(…)`: `$(plan-grok)` для Grok (`autoPercentUsed`), `$(symbol-misc)` для Other (`apiPercentUsed`), `$(credit-card)` для OD. Названия тарифа в строке нет; тариф — в подсказке и на дашборде. По краям группы: `|` в начале первого метра и в конце последнего; между метрами `|` нет. Значок Grok — свой, через `contributes.icons` и файл `media/grok.ttf` (не `.woff`: загрузчик Cursor отдаёт `.ttf` вне корня папки расширений, а ярлык установки раскрывается в реальный путь). Проценты — с одним знаком после запятой, без `%`. Слова Grok, Other и OD остаются в подсказке и на карточках. На карточке дашборда вместо слова Grok — тот же контур как SVG. OD (`spendLimitUsage`) показывать только при расходе больше нуля. `totalPercentUsed` в интерфейс не выводить. Фон пунктов (`backgroundColor`) для расхода не красить. Grok / Other / OD — отдельные `StatusBarItem`. Пункт `status` с `$(pulse)` только при загрузке или ошибке. Grok и Other: `color` при проценте ≥ 80 (`#c4622a`; токен `charts.orange` на строке блеклый) или ≥ 100 (`charts.red`). OD при любом показанном расходе всегда `charts.red`. На карточках дашборда цифра красится теми же порогами: `#c4622a` и `charts.red`; цифра OD всегда красная.
- Статусбар: `StatusBarAlignment.Left`, приоритеты подряд от `Number.MIN_SAFE_INTEGER + 2` (Grok) до `Number.MIN_SAFE_INTEGER` (OD), чтобы группа стояла у правого края левой зоны.
- Токен, cookie и почту не писать в репозиторий, логи и ответы. В базе только `SELECT`. В интерфейс попадают короткие коды (`keychain`, `http-401`, `bad-response`), не текст ответа и не команда `sqlite3`. События без своей почты не показывать, если в ответе почта есть.
- Один проход обновления читает сессию и снимок тарифа по одному разу. События лежат в постоянном кеше `events-cache.json` в каталоге globalStorage расширения: уже закрытый интервал повторно не запрашивается, с сервера берутся только дыры и хвост до текущего времени. Если восемь страниц пришли целиком и идут от новых к старым, закрывается только кусок строго новее самого старого события, и следующий запрос идёт в дыру левее. Если порядок другой, окно режется пополам по часам. Каждый закрытый кусок сразу пишется на диск. Нулевая полоса на графике честна только внутри закрытого интервала; открытая дыра нулями не рисуется. Сводка моделей считается по загруженным событиям. Если список оборвался по времени после части страниц, эти страницы остаются на графике и в таблицах, а дыра не помечается закрытой. Если новых страниц нет, панель оставляет уже известные события, помечает их устаревшими и пишет, что новых нет из-за таймаута. Если не пришла ни одна страница и кеша тоже нет, панель оставляет прежние строки и не подменяет их сводкой биллинг-цикла. Пустой успешно загруженный период оставляет таблицу моделей пустой.
- Таймер не опрашивает окно без фокуса и не тянет события для скрытой панели. Скрытая панель обновляется, когда её снова показывают. Смена периода во время уже идущего запроса ставит ещё один проход, а не теряется.
- Запросы к `cursor.com` для списка событий ограничены дедлайном **180 секунд**. Одна страница ждёт ответ **30 секунд**. Если интервал закрыт целиком, дни без событий остаются на графике с нулём, не длиннее 62 дней. Дни в ещё открытой дыре нулями не рисуются.
- Слушатель сообщений webview регистрировать до присвоения `webview.html`.

## 3. Проверка

Перед сдачей правки:

```bash
node --check extension.js && node --check session.js && node --check settings.js && node --check usage.js && node --check usage-model.js && node --check event-cache.js && node --check dashboard.js && node --test
```

`node --test` гоняет чистые функции из `usage-model.js`. Поведение панели проверяется в открытом дашборде Cursor.
